## Security/scientific boundary, and next task
This entrypoint is now **genuinely guarded when invoked**, and its CLI disallows silently omitting the trusted external checkpoint SHA/latest ordinal. Nonetheless **the general-purpose lower-level `ingest` can still be invoked separately**. There is no protected central gateway forcing other callers or all future batch jobs to use this new wrapper. The original Google part375 DB checkpoint is separately pinned in repository Git history, but there is **no independently signed timestamp, remote append-only ledger, hardware identity or enforcement against compromise/rollback of the trusted Git history or CI workflow itself**. A caller that accepts untrusted or stale pin inputs can be misled; trusted head must come from a separately authenticated location/commit. The wrapper is intentionally **resume-only for already processed part375**, not a real multi-file/batch ingestion engine. Future production source ingestion needs protected workflow policy and externally persistent trusted batch-head updates, cost/retry quotas and original full GCS checksums.
