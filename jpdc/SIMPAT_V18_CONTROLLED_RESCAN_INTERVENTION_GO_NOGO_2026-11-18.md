## Important interpretation: LOCAL INTERVENTION, NOT GENERAL CAUSAL VALIDATION
The after-update waiting rescan is an **implemented change to the scheduling model**, not a fix validated as more correct or a generalizable IoT/IIoT enhancement. It provides valuable local counterfactual evidence that rescan timing matters for observed list states in two pre-known deterministic fixtures. Because it changes queued membership and downstream scheduler behavior, it is not independent holdout data nor isolation of all possible underlying causes. No proof a library bug exists, native EXEC list equals physical CPU started, or the entire A2 24-condition waiting residual is explained. The synthetic threshold sweep remains posthoc, not an independent result.
