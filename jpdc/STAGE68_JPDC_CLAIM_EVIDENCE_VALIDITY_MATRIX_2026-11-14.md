## Evidence-strength hierarchy and prohibited conflations
1. A software unit test, independent artifact replay or green GitHub Actions result demonstrates **implementation/reproducibility**, not a policy-effect result or physical equivalence.
2. Shadow availability is not actual routing, nor is historical sampled positive-residual maximum a finite-sample conformal guarantee. Per-node empirical feedback is **missing not at random** because existing routing decides which nodes receive observations. Counterfactual performance on unchosen nodes is not measured.
3. The true statistical unit for source-based paired scientific claims is the **independent source seed**. Multiple task rows, scenarios, policies and repeated workflows within a seed are **dependent** observations.
4. Do not select the best seed, drop harm from all-period MISSION, change the primary no-harm criterion, or report raw pooled decline as significance. Stage65 remains FAIL.
5. Native Java micro-traces cannot validate the independent 30k strict-FCFS Python result; the original 5ms fidelity gate remains FAIL. Queue-list membership is not necessarily actual CPU execution start.
6. No evidence of formal uncertainty coverage, reliable published-comparator replication, real IIoT evaluation or clean JPDC policy superiority. These are **blocking gaps**, not optional caveats.

## What remains sufficient for a defensible manuscript today
The present work supports a rigorous **negative-results/methodology/measurement study** about feedback observability, robust scheduling failure modes and simulator-specific queue semantics, with exact source and artifact provenance. It does **not yet support** an abstract claiming a superior robust cloud-edge scheduler. Any claim of a new scheduling algorithm's benefit needs a genuinely novel and frozen design, independent baseline implementations, new development seeds, prospective disjoint holdout, plus a defensible physical/workload domain.
