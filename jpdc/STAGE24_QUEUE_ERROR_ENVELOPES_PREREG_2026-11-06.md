## Explicit model and testable extension
At dispatch time t, p_j is the currently available nominal predicted end-to-end latency, n_j is task-specific nominal network time. Define actual time as `T_j = p_j + e_j + q_j`, where `e_j` denotes network excess and `q_j` denotes **total remaining nominal prediction error** (including queue/wait model mismatch and unmodeled non-network effects). Avoid double-counting: any residual that contains network deviation must not be used as q_j. Network intervals derive from Stage10's E2E-delivered observer, conditional on synthetic L=.0001/ms, epsilon=0, measurement age<=10000ms. Queue-error intervals must be supplied by a **separate source**, with a bounded issuance timestamp, validity period, nonempty context key matching the current workload/queue prediction model, and strictly causal observation/delivery. The controller will neither invent a queue bound nor interpret an empirical point residual as a deterministic bound. Future queue estimators must be separately calibrated/validated.

**Decision:** given a nominated reference g (initially nominal greedy), a candidate j!=g may be selected only if both reference and candidate have nonexpired, context-matched queue-error intervals and accepted nonstale Stage10 network envelopes, and
`p_j+Ue_j+Uq_j+1e-9 < p_g+Le_g+Lq_g`.
For MISSION additionally require `p_j+Ue_j+Uq_j<=deadline`. Other tasks may apply robust change with no probing. If either side lacks usable evidence, if no dominance, if a certificate was revoked or the policy time is earlier than delivered data, **ABSTAIN** and follow explicit deterministic g; it is NOT a certified safe choice. q intervals must permit signed errors, unlike nonnegative network excess. Do not look at hidden affected-node masks, physical next-free timestamps or future task completion.

## Conditional proposition, not empirical safety guarantee
Assuming actual network excess `e_j∈[Le_j,Ue_j]`, actual non-network residual `q_j∈[Lq_j,Uq_j]` for both the candidate and reference at this **specific dispatch**, and the same correctly defined p_j, then the strict inequality yields `T_j<T_g`. If additionally upper total <=deadline, then candidate meets that deadline **under those assumptions only**. If a bound is invalid, stale, inferred from future data, or wrong context, the claim can fail; do not call this an empirical coverage certificate, CP guarantee or theorem of general scheduling performance.
