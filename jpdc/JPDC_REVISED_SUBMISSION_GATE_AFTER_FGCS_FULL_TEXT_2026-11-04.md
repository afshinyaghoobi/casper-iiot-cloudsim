1. Source-matched 4-seed controlled **fault-location mask and effective-eta factorial intervention** (not in FGCS first-paper experimental design). Valuable experimental method, but deliberately extreme pre-change-derived masks; exploratory sign p=.125, no confirmatory benefit.
2. Separate disjoint 10-seed fixed-eta primary Java test (not the original FGCS 30-seed baseline campaign), exact two-sided sign p=.0625, nonsignificant.
3. Independent native Python physical engine, raw outcome-driven calibration, all eight same-model policies and 10 new predeclared seed60–69 evaluations; outcome p=1.000, nonsignificant; original queue parity test FAIL >5ms vs 9.1214ms.
4. Genuine observed rank2 counts (FULL 39; rank3 zero), missing in first-paper stored logs. This strengthens software observability but does not establish causal effectiveness of rank selection.

**Original algorithm repeats:** all candidate definitions, equations (1–10), original CP memory/controller, health/probing, Algorithm 1, eight policy modes, and five underlying synthetic scenarios already belong to the first FGCS work.

## Revised actionable program (choose after originality gap, not from holdout p-values)

**Path X — new mechanistic scheduling method.** Define a rigorously new pre-dispatch risk-aware control step using information genuinely observable before scheduling. Its formal decision rule/optimization target, assumption set, complexity and possible safety/calibration properties must differ clearly from first FGCS Algorithm 1. The proposed exposure/queue term currently exists as an *idea*, not an implemented/verified algorithm. Evaluate on independent new development data; freeze a new disjoint holdout. Do not tune on used seeds0–69. Distinguish policy effectiveness from certificate quality.

**Path Y — standalone systems causality study.** Make the **intervention design**, not the known certificate/deadline distinction, the core new research question. For example, isolate service-health exclusion vs probing in a 2×2 factorial with independently randomized fault locations/topologies and a second different queue/simulator or new workload distributions. Existing four deliberately selected seed masks and nonsignificant tests are only pilot evidence. A paper must independently answer an identifiable, new question FGCS did not answer; carefully reference the first work.

Both paths have substantial extra work. **NO submission-ready new JPDC paper at present**, irrespective of the success of prior engineering tests.
