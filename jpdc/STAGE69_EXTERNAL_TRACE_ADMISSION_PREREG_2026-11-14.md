# Stage69 pre-evaluation data-admission protocol — independent production traces (2026-11-14)

This stage is **external trace SOURCE/SCH​EMA screening and a parser-gating tool**, not acquisition or replay of real row-level workload observations. Do not assert any new independent performance, deadline or Java validation. Existing Stage65 independent source-n8 safety FAIL and original Java-Python queue-parity FAIL remain immutable. Before running any trace-informed scheduling claim, a source must pass the exact tests below or be explicitly restricted to a narrower experiment.

## Source requirements, strictly distinguished
1. **Provenance**: official origin URL, dataset release and version, dataset-level reuse/license terms verified from authoritative publisher, original immutable source checksum for any acquired archive, original row IDs, exact timestamp units, disclosure of filtering/exclusions.
2. **Arrival vs execution start**: identify a documented **submission/creation event**, not merely job scheduling/execution start. Delayed placement, truncation and failed/censored events must not be silently recoded as actual arrivals/completions.
3. **Compute**: distinguish requested CPU cores, CPU utilization, total consumed CPU time, elapsed job execution duration and task 'work' in the simulator's artificial formula `work / capacity * 12`; there is no generic unit-preserving transformation between these fields. An undocumented scaling factor is **synthetic augmentation**, not measured source work.
4. **Network and deadline**: distinguish machine-level normalized ingress/egress from per-task input/output transfer in MB, and an observed task deadline/SLO from an invented relative deadline. No filling missing values with zeros. If deadline synthetic, frame as trace-arrival/replay + **synthetic deadline scenario**, not externally validated deadline-aware effectiveness.
5. **Machine matching**: resource measurement and machine ID join, anonymization and time window, concurrency/PE scheduler policy; original data-center traces are **not industrial IIoT edge/cloud deployments**.
6. **Source-independence**: frozen train/DEV/test separated by independent periods/clusters/jobs (and documented temporal gaps); reusing Stage65 synthetic seeds in a new real trace is not a new external holdout.
7. **License**: Google's official `google/cluster-data` README explicitly says trace + documentation under CC BY. For Alibaba's official `alibaba/clusterdata`, dataset-use/republication terms need a separately checked publisher statement; do not infer CC BY from Google or from GitHub visibility.

## Strict eligibility codes for future machine-readable manifest
- `FULL_EXTERNAL_ONLINE_DISPATCH`: **independently observed** submission arrival time, task compute work in documented physical units, per-task network transfer with documented units, observed task deadline, machine capacities and sufficient topology, verified license, actual rows and units all present. No synthetic imputation. Do not use this label absent all fields.
- `TRACE_ARRIVAL_RESOURCE_ONLY`: independently observed submission/creation time and at least one documented resource field; missing task network and/or observed deadline are **explicit**. Can validate arrival process/resource heterogeneity only. Any simulated deadline/network is *synthetic*, clearly separated, and cannot confirm real deadline/network performance.
- `TRACE_PLACEMENT_AND_RESOURCE_ONLY`: execution start/end timestamps or utilization provided without demonstrated submission time. Allows descriptive placement/usage/elapsed-runtime analysis, but not claimed arrival-driven queue evaluation. Reconstructing arrival from execution start is prohibited.
- `DOCUMENTATION_ONLY_PENDING_ROWS`: schema/docs and terms seen; no independently retrieved data rows audited. This is the **current Stage69 evidence status for all candidates**.
- `BLOCKED_PROVENANCE_OR_LICENSE`: required source or license unknown for any **intended redistribution** or publication of derived data; can consider narrower metadata-only citation but not claim unrestricted redistribution.
- `REJECTED_MALFORMED`: malformed timestamps, negative durations, inconsistent units, missing data or unverifiable machine joins.

## Cohort candidates selected before any row-level performance results
**Alibaba Cluster Trace 2018** (first targeted source): official publisher `https://github.com/alibaba/clusterdata` and authoritative schema `https://github.com/alibaba/clusterdata/blob/master/cluster-trace-v2018/schema.txt`. Source says 4k machines and about eight days, batch-task and batch-instance start/end, cpu utilization/plan_cpu, machine/net usage columns (normalized), DAG labels. **Execution START is not proven arrival**, and machine normalized network usage is not per-task input/output MB. No observed relative task deadlines documented in the inspected schema. Publisher's dataset licensing/republication terms not independently verified here. **Status DOCUMENTATION_ONLY_PENDING_ROWS**, not admitted for full CASPER dispatch.
**Google Borg ClusterData2011 v2.1**: authoritative `https://github.com/google/cluster-data/blob/master/ClusterData2011_2.md` and official root `https://github.com/google/cluster-data`; approximately 29 days and 12.5k machines, event data plus usage measurements, known missing event/measurement caveats; official CC BY. Potentially plausible **submission event** replay after reading exact schema/records, not yet verified row-level. No directly observed per-task network transfer+deadline combination established from documentation. **DOCUMENTATION_ONLY_PENDING_ROWS**.
**Google Borg ClusterData2019 v3**: official `https://github.com/google/cluster-data/blob/master/ClusterData2019.md`, eight cells May2019, resource requests, 5-min CPU usage histograms, published via Google BigQuery (~2.4TiB compressed according to documentation), CC BY. Not a measured task-level E2E/industrial SLO workload; requires a query budget, explicit schema and original row audit. **DOCUMENTATION_ONLY_PENDING_ROWS**.
