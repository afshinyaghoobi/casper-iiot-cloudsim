## Desired safety contract
1. Add a per-file canonical SHA256 digest over each complete SQL set of `(job_id)` and `(job_id,task_index)`, and per-file event-type/count canonical digest, with explicitly versioned unambiguous signed 64-bit integer encoding and domain separation. Preserve exact integer identifier values, stable ascending SQL order, and avoid constructing complete sets in Python. Store file digests and row counts **in same commit transaction** as event counts and COMPLETE file_inventory marker for newly ingested sources.
2. On every `ALREADY_VERIFIED_NOOP`, after exact source SHA/version check, verify database `PRAGMA quick_check`, file row count, canonical complete job/task/event digests recomputed directly from SQL rows and row cardinalities against stored immutable-at-commit digest metadata. If missing digest metadata from the legacy DB, **fail closed**, unless a separate explicitly authorized migration examines the genuine old full original gzip and establishes complete source↔SQL key equivalence before storing digests. Simply taking a digest of old potentially corrupted SQL and calling it verified is FORBIDDEN.
3. Safe migration of the old artifact requires exact archive SHA, full source original GCS generation, independently constructed original source job/task SET and source event histogram matched to the old SQL tables, source gzip terminal integrity, original row/time units and counts, before a transaction inserts the canonical digest record. This migration is NOT source-independent replication; it upgrades verified OLD original data. The historical old SQLite artifact MUST remain immutable; operate on copies only.
4. Specific synthetic negative controls: after successful indexing, **delete one job and task**, or **replace one job or task with another valid same-count value**, or **swap event type counts with total unchanged**, and attempt actual resume; all must fail before `ALREADY_VERIFIED_NOOP`. Altered source SHA/generation must fail. Missing digest metadata must fail. Crash after 1024 buffered rows must roll back. Exact original spent source SQLite copy must first fail legacy resume before migration, migrate using source-backed exact set verification, then succeed original resume with no extra rows; after tampering same-cardinality key it must fail.

Preserve bounded 1024-row writes and sequential per-file SQL digest streaming, cap raw gzip payload and decoded rows, keep original source E42 Git blob `34256ca7bff46f911cf20e8b94278fbd09175746`, rejected Stage64 Python policy blob `24d495dba4d29f8fe070ad6539b20361a7193cc6` immutable.
