# JPDC Stage10 — dimensionless network slowdown and delayed observed change alarm
**Pretest design registration (2026-11-05). This is an assumption-sensitive prototype, not a verified algorithmic improvement or a new theorem.**

## Source model diagnosis
The frozen original independent physical-duration implementation defines for task i, node j:
`nominal_net_ij = RTT_j + 8000(input_i+output_i)/bandwidth_j`;
`actual_net_ij = nominal_net_ij * network_multiplier(i,j,scenario)`, where in the hidden 50%-bandwidth S3 scenario the physical module actually multiplies the ENTIRE nominal network latency by 2 for selected affected nodes after task index10000. This implements a *whole-network-latency multiplier*, not a physical bandwidth-only transfer-time change; we must not misdescribe its RTT behavior. Its strict FIFO CPU service model differs from original CloudSimPlus SpaceShared (pre-existing queue parity test FAIL), and network measurement availability remains stylized after CPU finish. No independent packet-level network traces have been validated.

The Stage8/9 node-level *absolute millisecond excess* `actual_net-nominal_net` depends on task size and nominal path latency. Two tasks with the same hidden network multiplier but different input/output sizes produce incompatible absolute millisecond excesses if epsilon is small. This motivates the dimensionless normalized observed slowdown `z_ij = max(0, actual_net_ij/nominal_net_ij -1)`, observable only when E2E feedback arrives. Under the specific source generator multiplier, z=0 for unaffected, z=1 for S3 affected after the task-index shock. This simple normalization matches source algebra but is **not new algorithmic novelty**.

## Registered new feedback state and no-overclaim contract
Create a standalone 21-node pure Python `NormalizedObservedNetworkEpochs` object. Each node has an independently observed epoch ID initially 0, a list of accepted reports for that epoch, last newest measurement generation timestamp, detected-change count and anomaly counters. A report `(node, actual_net_ms, nominal_net_ms, m_generated, d_delivered)` becomes available only when `d<=decision_time`; enforce global nondecreasing delivery. If m_generated is older than latest accepted measurement timestamp on that node, **quarantine** it for diagnostic counting rather than applying it to current epoch (this is a conservative restriction, not a proof that newer data are correct).

Within one epoch, assume the **dimensionless node slowdown** follows `|z_j(t)-z_j(s)|<=L_j|t-s|` with externally specified L_j and observed normalized measurement error <=eps_j; apply the exact Stage8 historical pairwise consistency test on normalized z in that epoch (store all accepted reports for transparent audit). If a *newer* delivered observation contradicts any accepted report under fixed L and eps, report `change_alarm=True`, **increment a detection counter only when the contradictory E2E observation is delivered**, quarantine/retire older epoch (not silently accepting it as compatible), and start a new single-observation epoch. Do not declare that the true physical change point was found or that the network is safe between the actual hidden shock and first alarm. The exact hidden affected-node mask and source shock task index are used ONLY by separate truth-grounding fixtures, NEVER by selector.

If observed data are consistent, the current epoch's age-aware normalized excess interval is `[LOW_z,HIGH_z]`; convert it to task-specific additional network latency bound `[nominal_net*LOW_z,nominal_net*HIGH_z]`. When no report has ever arrived, return unknown ([0,infinity]); after change alarm, the single fresh observation starts a new epoch but the model must carry `unverified_after_alarm=True`: a single new observation cannot prove stability of a regime. Under ordinary no-alarm epochs, model validity still conditional on external drift/noise assumptions (not a conformal guarantee). The model cannot certify real E2E task deadlines, as CPU and virtual-queue errors remain uncontrolled.

## Frozen deterministic fixture matrix
1. Task-size scaling invariance: nominal network durations 20ms and 80ms with same source multiplier 2.0 must both report z=1; absolute extra network latencies differ (20ms vs 80ms).
2. Source S3 ground truth without oracle in inference: on an affected node pre-shock multiplier1 then post-shock2; with normalized L=.0001 per ms, epsilon0 and measurement generation dt=10ms, abrupt jump z0→z1 must raise change alarm only at E2E feedback delivery, not at task arrival/CPU completion or hidden shock timestamp.
3. No decision before delayed E2E result has access to the jump; pending unreported observations never affect epoch.
4. New epoch resets old history; a single post-shock feedback cannot be used as proof of stable model or as a real latency guarantee. A newer compatible observation may remain unverified until an explicitly declared minimal evidence count; this is a descriptive gate, not proof of true network stationarity.
5. Late-delivered older-generated feedback is quarantined without corrupting the newer epoch; no info leak, no retroactive change alarm.
6. Within-epoch consistent gradual change produces exact Stage8-like interval scaling times current task nominal network duration, and finite low/high with valid assumptions.
7. Invalid negative/nonfinite actual and nominal durations, time m>d or global delivery earlier than last delivery, out-of-range node fail closed without mutating accepted state.
8. Execute a 21-node synthetic source-consistent counterexample with different RTT, bytes and (affected/unaffected) multipliers; fixed-source physical multiplier inference must match reported normalization and change alarms. This is a *controlled algebra/logic fixture*, NOT a new real 21-node native scheduling trial.
9. A true restoration to multiplier1 after previously observed multiplier2 must also be detected only from completed feedback.
10. Include a negative case: high observation error epsilon>=.5 means z=0 and z=1 are compatible; NO change alarm claimed. Detectability depends on assumptions and measurement power.
