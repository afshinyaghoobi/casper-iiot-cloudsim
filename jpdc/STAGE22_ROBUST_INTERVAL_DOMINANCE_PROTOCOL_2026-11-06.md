## Frozen Stage22 theoretical proposal (before unit-test outcome)
Derive an **assumption-conditioned robust-dominance certificate** from *causally delivered E2E* network-excess observations and current dispatch-time **nominal queue-aware predictions**. Unlike Stage15's ad hoc +2ms nominal detour or active probing, switch away from the nominal greedy reference node `g=argmin_j(p_j,j)` only if:
1. Reference node `g` has at least one accepted delivered observation in the **current epoch**, is not under the `post_alarm` unverified flag, and has a finite lower extra-network bound `Lextra_g >=0`.
2. Candidate `j!=g` also has accepted delivered observations, is not `post_alarm` unverified, and has finite upper extra-network bound `Uextra_j`.
3. Candidate upper predicted end-to-end latency `p_j + Uextra_j` is **strictly less** than reference lower predicted latency `p_g + Lextra_g` by at least a predeclared numerical margin `1e-9ms`. This is the *only* reason to switch; absent such evidence choose original greedy `g`.
4. For MISSION class require candidate's upper predicted latency <= task deadline. NORMAL decisions may use same robust criterion but **never explicitly reroute merely for probing**. Every Nth NORMAL opportunity is not a separate probe.
5. For all candidate bounds, require the source model's freshness/epoch compatibility from Stage10 (`MAX_FRESHNESS_MS=10000`, synthetic `L=.0001/ms`, `eps=0`). These are explicitly uncalibrated assumptions, not learned guarantees. Compare all eligible candidates by minimum upper bound; ties by node index. No hidden shock onset or true physical service time enters the controller.

## Conditional, deterministic theorem and important counterexample
Write true end-to-end decision-time latency as `T_j=p_j+e_j+q_j`, where `p_j` is the causal nominal prediction, `e_j` is its extra-network latency, and `q_j` is the error in nominal prediction due to queue physics/model. Given *explicit assumptions* `e_j∈[Lextra_j,Uextra_j]` for every eligible node and `q_j=0`, if the new policy switches to j, then `T_j<=p_j+Uextra_j < p_g+Lextra_g<=T_g`. Thus the strict improvement holds for **exact input queue model and valid interval envelopes only**. Also `T_j<=deadline` for MISSION if its upper bound is deadline-feasible. When `q_j` unknown, the assertion can FAIL. Example: candidate p_j=10, upper extra=0; reference p_g=9, lower extra=3; the rule selects candidate with nominal upper10<12, but real candidate has queue error +10 while reference has zero -> actual20>12. This is a critical falsification, not a minor caveat. No cross-simulator real-world deadline guarantee.
