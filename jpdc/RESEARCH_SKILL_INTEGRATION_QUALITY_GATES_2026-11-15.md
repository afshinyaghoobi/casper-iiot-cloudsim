## Equation-to-code reference (current method, NOT a new theorem)
Frozen Stage62 `jpdc/partial_observation_selector_stage62.py` defines eligible observed candidate subset `E(t)`, with CPU sample count≥4, E2E count≥8, both freshness≤5000ms, telemetry≤100ms and `|E|≥2` plus nominal greedy `g∈E`. Under four **heuristic** sample-max worlds `W`, selected candidate minimizes the implemented lexicographic tuple
`( max_{w in W} 1[L_j(w) > D], max_{w in W}(L_j(w)-min_{k in E}L_k(w)), predicted_latency_j, j )`
over `j∈E`. Equality to deadline is **not** a miss in this code (strict greater-than); this is a code contract, **not** proof that the actual physical deadline event uses identical boundary semantics. Costs are `pred[j] + positive_cpu_residual_max + positive_network_residual_max` per chosen world. `pred` is a current predicted E2E latency; if its queue/network contributions overlap residual definitions, conservatism/double counting requires a separate structural audit. Original Stage64 uses the heuristic choice only for MISSION, otherwise original FULL, with fallback whenever the observer ABSTAINs. On-policy histories are policy-dependent; unknown alternate node service is censored. No finite-sample coverage theorem is presently valid.

**Equation-guide implementation detail requiring manuscript precision:** the Stage62 function accepts `nominal_network_ms` as a 21-entry argument and validates its lengths/finite values, but does **not** subsequently incorporate that argument into its ranking expressions. Instead `predicted_latency_ms` is already an end-to-end prediction (and `predicted_latency` in `jpdc/independent_workload_generator.py` includes RTT and transfer time), while the selector adds historical positive CPU/E2E excess. This can be entirely consistent with a nominal E2E forecast, **but** it means the supplied `nominal_network_ms` vector has no independent influence on the selection at fixed `predicted_ms`; do not describe a separate nominal-network optimization term or call this a demonstrated missing network penalty. A synthetic-code negative/invariance fixture in `test_research_quality_integrated_gates.py` verifies this behavior. A separate task-by-task decomposition would be required to prove that the E2E excess is not double counted.

Complexity *of the isolated selector* given K=|E|≤21, H=4 scenarios, and bounded residual buffers length≤32: eligibility O(21), scanning histories O(K·32) if `max` computed for each world and each eligible node; world minima and scores O(H·K). With this fixed small setting it is O(21+K·32+H·K), **not a bound for total original CASPER scheduler runtime**. Strictly do not imply a novel approximation algorithm or distribution-free bound.

## Permanent research gates
1. **Problem + novelty**: original FGCS E42 contribution overlap checked; exact closest prior source and author-fidelity.
2. **Math + causal input**: dimensional consistency, actual dispatch-time available state, exact definition of wait/network cost and deadline, uncertainty guarantee requires assumptions and proof.
3. **Physics + data**: Java SpaceShared vs Python strict FIFO gap acknowledged, genuine trace creation/submit events vs scheduling starts, no fictional network transfer/deadline, provenance/license/version/checksum.
4. **Experimental independence**: protocol committed before outcome, fresh separate DEV vs untouched holdout, original frozen baseline parity, independent source seeds statistical unit, exact paired risk and fail-closed primary safety, no winner selection or thresholds changed post hoc.
5. **Evidence + manuscript**: technical CI ≠ empirical/scientific pass; original artifacts independently checked, negative rows reported, manuscript claim wording constrained.
