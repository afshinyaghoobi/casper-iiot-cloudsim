## Hypothesis and new rule (never use hidden fault IDs or future outcomes for decisions)

For every observed task i and node j, the original task nominal network time is `n_ij = RTT_j + 8000(inputMB+outputMB)/BW_j`. Maintain per-node FIFO of the **last 32 nonnegative network excess observations** `e_{ij}=max(0,measured_e2e_network_ms - n_ij)`, updated only at **end-to-end feedback arrival** `actual_cpu_finish_ms + measured_e2e_network_ms` in our separately executable native strict-FCFS pilot engine. This conservative feedback timing makes neither post-CPU network transfer nor fault label visible at the physical CPU-finish event. If fewer than **8 observations** exist for a node, penalty=0; otherwise `r_j=nearest-rank empirical 0.90 quantile(last32 e_ij)`. At arrival i, choose
`j* = argmin_j [predicted_latency_ij(t_i, virtual_backlog_i) + r_j]` with stable lowest-ID tie, among all 21 nodes. No hidden affected-node mask, physical next-free, stochastic realized service, future task attributes, original Java traces, telemetry true fault flags, CP coverage labels or current event outcomes may enter policy selection. Observations arrive strictly after the task's end-to-end completion time, not at dispatch. All node risk states start empty (no data-dependent tuning using old seed60–69 outcomes). Complexity O(N * W log W) naive quantile selection per arrival (N=21, W=32); memory O(NW) vs original predicted greedy O(N). Per-node window is a simple robust online heuristic, NOT a conformal guarantee, and a re-ranking invalidates directly interpreting original rank-conditioned qhat as a calibrated bound.

## Pilot implementation and physical-time safeguards
- Use independently generated task streams and source-matched native physical durations in strictly FIFO 21-node CPU queues, **not Java outcomes**.
- Two event types (CPU finish and observed network feedback) are distinct. Physical CPU nextFree and arrival dispatch are computed by the *physical process*, and are never directly read by the NEW policy (only nominal virtual queue estimates allowed).
- The NEW network residual is observed only at `CPU finish + actual network duration` with stable tie ordering: completed feedback before simultaneous arrival; deterministic tie-order among task IDs.
- Set risk quantile based only on previous observed tasks from that node. Keep fixed feedback delay even for baseline arms for strict comparability when measuring observed mechanism events. A future enhancement should account for upstream request network timing; this is deliberately a synthetic post-CPU observation semantics and not a real packet-level model.
- Unit/falsification fixtures: no data update at dispatch/CPU finish, no future fault leakage; positive network excess on a completed node changes rank after 8 samples; missing-data threshold leaves greedy unchanged; clipping negative excess to zero; shock-invariant decisions before any feedback; comparator original greedy event physics parity; task and node conserved; byte-identical full pilot rerun.
- Report how many NEW actual nonzero risk penalties, baseline-to-NEW node reroutes, postshock damaged-node dispatches, postshock Mission misses, and actual full E2E feedback events occurred. **No positive performance claim** or positive-results paper from this small pilot.
