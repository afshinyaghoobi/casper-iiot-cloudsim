## Frozen NEW probe rule, no oracles
New policy `NEW_NETWORK_RESIDUAL_PROBE` keeps the original `NEW_NETWORK_RESIDUAL` decision and its 32/8/q90 parameters unchanged on every non-probe arrival. On **every 100th NORMAL task arrival only** (one opportunity, no catch-up or budget rollovers), eligible node candidates are those whose **nominal virtual-queue-based predicted end-to-end latency <= that NORMAL task's original deadline**. Do NOT use hidden fault mask, physical CPU next-free, actual network, future outcomes or CP leakage. The probe's target is the eligible node with **fewest E2E feedback observations seen so far**, then **oldest last completed E2E feedback ordinal** (never seen first), then **lowest nominal predicted latency**, then node index. If chosen target equals ordinary risk routing's choice, count it as a probe attempt with zero extra reroute cost; otherwise it is an actual intervention. The chosen task, not a synthetic zero-cost packet, runs through the same physical CPU FIFO server and network delay, so probe costs, deadline misses and downstream queue interference are real in this model. Eligible set may be empty; record skipped opportunities and apply the no-probe decision. No mission task is directly probed; any mission impact is from changed resource queues and network risk estimates.

No exploration randomness, no tuning after seed82 data. Maximum **floor(NORMAL arrivals /100)** opportunities, ≤1% of NORMAL arrivals (not total tasks). The original health-policy sparse probes are separate and must not be mistakenly counted as network-risk probes. A node gets exploration state updated ONLY after physical E2E feedback of an actual task, not dispatch or CPU finish. Probe on NORMAL workload is not an unbiased estimate for MISSION task network distributions; preserve this limitation.
